# 탑다운 2D 리듬 슈팅 게임 구현 계획

## 1. 목표와 작업 원칙

- 같은 폴더의 `기획.md`를 게임 규칙의 기준으로 삼는다.
- 사용자가 새로 만든 MainScene에서 처음부터 구현한다. 씬을 다시 만들거나 덮어쓰는 방식 대신 필요한 오브젝트를 단계적으로 배치한다.
- 구현에 앞서 앞선 프로토타입에서 만든 스크립트·에셋·테스트·보조 파일을 모두 삭제한다. 해당 코드를 복사하거나 수정해 재사용하지 않고 현재 기획에 맞춰 새로 작성한다.
- 첫 목표는 짧은 곡 구간에서 방 이동 → 적 처치 → 문 파괴 → 다음 방 이동을 끝까지 플레이할 수 있는 프로토타입이다.
- 방, 문, 적, 플레이어, 판정선, 조준 호, 대상 표시점, UI와 테스트용 효과는 가능한 한 씬에 미리 배치한다.
- 등장과 소멸은 미리 배치한 오브젝트의 표시 상태 변경으로 처리한다. 실행할 때 맵을 생성하지 않는다.
- 게임 규칙과 음악 시간, 채보 데이터, 시각 연출을 분리한다. 연출이 끝나야 판정이 확정되는 구조로 만들지 않는다.
- 구현은 아래 단계 순서로 진행한다. 단계마다 확인 가능한 결과를 남기고 다음 기능을 연결한다.
- Unity 실행 및 플레이 검증은 사용자가 담당한다. 개발 중에는 컴파일, 순수 로직 검사, 씬 참조 검사로 확인한다.
- 실제 작업 시 해당 단계와 직접 관련된 파일만 조사한다.

## 2. 책임 분리

다음은 구현 책임을 나누기 위한 구성안이다. 클래스명은 구현 시 정하되 역할의 경계는 유지한다.

| 구성 | 책임 |
| --- | --- |
| 음악 시계 | 예약 재생, 곡 경과 시간 제공, 정지 및 재시작 |
| 채보 데이터 | 방 순서, 등장 시각, 이동 방향, 문 시각과 이동 간격, 적의 방향과 시각 |
| 채보 검증 | 불가능한 시간 배치, 참조 누락, 잘못된 방 연결 등을 제작 단계에서 발견 |
| 시간 판정 | 입력 시각과 기준 시각으로 너무 빠름·빠름·정확·느림·너무 느림 계산 |
| 게임 진행 | 시작 대기, 플레이, 사망, 클리어와 전체 초기화 |
| 방 진행 | 현재 방과 바로 다음 방, 이동 중 상태, 방 전환과 적 등장 |
| 이동 입력 | WASD 누름 이벤트와 방향 전달, 이동 중 입력 폐기 |
| 조준·사격 | 마우스 방향, 대상 선택, 클릭 시각 판정, 선택된 적 표시 |
| 방·문·적 표시 | 음악 시간에 따른 선명도, 판정선 크기, 문짝 위치와 표시 상태 |
| 플레이어·카메라 | 성공한 이동의 짧은 애니메이션과 카메라 추적 |
| 피드백 | 정확도, 실패 사유, 사격·명중·파괴 연출 |

한 컴포넌트에서 음악 재생, 입력, 모든 방 생성, 판정과 UI까지 처리하지 않는다. 작은 프로토타입에 불필요한 범용 프레임워크도 도입하지 않는다.

## 3. 데이터와 시간 기준

### 채보 및 씬 연결

- 곡과 채보를 묶는 데이터 에셋을 만들고, 안정적인 ID로 MainScene에 미리 배치한 방·문·적과 연결한다.
- 씬 오브젝트 참조는 씬의 연결 컴포넌트에 둔다. 데이터 에셋이 씬 인스턴스를 직접 소유하지 않도록 한다.
- 방 데이터에는 방 ID, 다음 방 연결과 방향, 등장 시각, 이동 시각, 문 유무, 적 목록을 둔다.
- 문이 있는 방은 문 판정 시각과 양수 간격 a를 편집하고, 이동 시각은 문 판정 시각 + a로 계산한다. 서로 다른 두 값이 충돌하지 않게 한다.
- 적 데이터에는 해당 방, 8방향 중 위치, 음악 기준 판정 시각을 둔다.
- 판정 구간, 이동 시간, 조준 각도·반지름, 초기 판정선 크기와 선명도는 설정값으로 분리한다.
- 제작 편의를 위한 BPM·박자 표기를 사용할 수 있지만 런타임의 판정 기준은 하나의 음악 시간으로 통일한다.

### 공통 시간 및 처리 순서

- 음악 DSP 시간을 기준으로 곡의 경과 시간을 계산한다. 프레임마다 deltaTime을 누적해 채보 시간을 만들지 않는다.
- 방 이동 성공 시각이 빨라지거나 늦어져도 이후 채보의 기준 시각을 변경하지 않는다.
- 입력 누름 시각과 판정 시각을 같은 시간축으로 비교한다. 입력 이벤트 시간의 변환은 한 곳에서 처리한다.
- 프레임 사이에 발생한 입력과 시간 초과는 발생 시각 순서로 처리한다. 프레임 끝에 만료되었다는 이유로 그 전에 발생한 유효 입력을 실패시키지 않는다.
- 성공 구간의 시작·정확 구간의 경계·느림 구간 종료를 명시적으로 정의하고 경계값 검사로 고정한다. 느림 구간이 종료되는 시각부터 미처리 노트는 실패다.
- 이동 애니메이션 중 WASD는 폐기하며 버퍼에 저장하지 않는다. 사격에는 이동 중이라는 이유만으로 별도 입력 무시 규칙을 추가하지 않는다.
- 재시작하면 시계, 미처리 입력, 처리된 채보 상태와 모든 표시 상태를 함께 초기화한다.

## 4. 단계별 구현

### 0단계 — 앞선 작업물 삭제 및 시작 상태 정리

작업:

- 앞선 프로토타입 제작 내역과 해당 경로의 실제 파일을 대조해 삭제 목록을 확정한다. Assets 전체를 재귀적으로 조사하지 않는다.
- `Assets/Scripts/MovementTest/`에 만든 이동·음악·요격 스크립트, 테스트 음원, 스프라이트와 관련 파일을 삭제한다.
- `Tests/InterceptionRulesChecks.cs` 등 앞선 구현에서 만든 테스트와 남아 있는 임시 생성·검증 스크립트도 삭제한다.
- 삭제하는 에셋의 대응 `.meta`도 함께 삭제한다. 폴더 전체가 해당 작업물로만 구성된 경우에만 폴더와 폴더 `.meta`를 삭제한다.
- 다른 경로에 앞서 만든 파일이 남아 있다면 제작 내역으로 식별되는 파일을 삭제 목록에 포함한다. 출처가 불명확한 파일을 일괄 삭제하지 않는다.
- 사용자가 새로 만든 MainScene, `기획.md`, `구현 계획.md`, 프로젝트 설정, 설치 패키지 및 사용자 작업물은 보존한다.
- 새 MainScene에 삭제 대상 스크립트나 에셋의 참조가 남아 있는지만 확인한다. 남은 참조가 있으면 해당 연결을 정리한다.
- 새 구현을 위한 폴더와 코드 구조는 1단계부터 필요한 만큼 새로 만든다.

완료 기준:

- 앞선 프로토타입의 스크립트·에셋·테스트·보조 파일이 확정한 삭제 목록에 따라 제거되어 있다.
- 새 MainScene과 두 기획 문서가 보존되어 있고, 씬에 삭제한 파일의 참조가 남아 있지 않다.
- 이후 구현과 검증이 삭제한 코드, 테스트, 음원 또는 스프라이트에 의존하지 않는다.

### 1단계 — 기반과 최소 이동 플레이

작업:

- 새 MainScene의 필요한 설정만 확인하고 플레이어, 카메라, 시작 방과 다음 방을 정적으로 배치한다.
- 방의 정사각형 외형, 네 모서리 ㄱ자 벽과 각 변 중앙 통로를 만든다.
- 음악 시계, 최소 채보 데이터, 시간 판정, 게임 진행 상태를 구현한다.
- WASD를 누르면 바로 다음 방의 방향과 시각을 판정한다.
- 성공 시 짧게 이동하고, 도착 후 이전 방을 숨긴다. 이동 중에는 WASD를 무시한다.
- 잘못된 방향, 너무 이른 입력, 입력 누락 시 사망하고 처음 상태로 재시작할 수 있게 한다.
- 최소 시작·재시작 안내와 결과 표시를 배치한다.

완료 기준:

- 플레이어가 방 중앙에서 대기하고 성공 입력 한 번에 한 방만 이동한다.
- 키를 누르고 있어도 반복 이동하지 않는다.
- 너무 이른 입력이 무시되지 않고 사망으로 이어진다.
- 이동 중 입력이 다음 방 입력으로 예약되지 않는다.
- 마지막 방 도착까지 처리한 뒤 클리어하며, 재시작 시 곡과 방 상태가 처음으로 돌아온다.

### 2단계 — 여러 미래 방과 이동 채보 표현

작업:

- 방향이 달라지는 여러 방을 배치하고, 각 등장 시각에 따라 미래 방을 표시한다.
- 바로 다음 방과 이후 회색 방을 구분한다. 선택 대상은 화면에 보이는 수와 관계없이 다음 방 하나다.
- 방과 큰 정사각형 판정선의 선명도를 음악 시간에 맞춰 높인다.
- 판정선을 줄여 정확한 시각에 방과 겹치게 하고, 그 이후에는 크기와 선명도를 유지한다.
- 이동 완료 시 다음 방 구분을 갱신한다. 이미 보이는 미래 방의 진행 중인 연출을 다시 시작하지 않는다.

완료 기준:

- 여러 판정선이 동시에 진행해도 입력 대상과 이동 순서가 명확하다.
- 빠름·정확·느림 어느 성공 시각에 이동해도 뒤의 채보 시각은 동일하다.
- 방을 빠르게 또는 늦게 이동한 뒤에도 미래 방의 등장·판정선 진행이 음악과 맞는다.

### 3단계 — 조준과 문 사격

작업:

- 플레이어 중심에 푸른 호만 표시하고 마우스 방향으로 회전한다. 부채꼴 내부와 중앙선은 그리지 않는다.
- 문과 적이 함께 사용할 수 있는 사격 대상 선택과 시간 판정을 구현한다.
- 표시된 미처리 대상 중 조준 부채꼴 중앙선과 각도 차이가 가장 작은 하나를 선택한다.
- 대상을 먼저 선택하고 시간을 판정한다. 대상이 너무 이르면 옆의 다른 대상 대신 클릭을 무효 처리한다.
- 대상 각도가 같은 경우에는 안정적인 채보 ID 순서 등 결정적인 처리 기준을 둔다. 판정 가능 여부를 우선순위로 사용하지 않는다.
- 좌·우 클릭은 각각 누름 한 번에 사격 한 번으로 처리한다. 유지 입력과 재사용 대기시간은 적용하지 않는다.
- 다음 방과 문을 동시에 표시하고, 두 문짝이 정확한 시각에 맞물리도록 움직인다.
- 정확한 시각 이후에는 닫힌 상태를 유지한다. 유효 사격이면 즉시 파괴 판정을 하고 문을 숨긴다.
- 문을 놓치면 마우스 방향과 관계없이 즉사하게 한다.

완료 기준:

- 문이 있는 방은 문 판정 시각 + a에 이동한다.
- 빈 클릭과 너무 이른 클릭은 사망이나 다른 대상 처리로 이어지지 않는다.
- 느림 허용 구간에도 문을 파괴할 수 있고, 놓치면 종료 시각에 사망한다.
- 클릭 판정은 총알의 비행이나 효과 종료를 기다리지 않는다.

### 4단계 — 방 내부 적 채보

작업:

- 각 방 내부의 지정된 8방향 위치에 적과 판정선을 미리 배치한다.
- 적 배치 거리는 조준 호 반지름 설정을 공유한다. 제작 시 배치와 설정의 일치를 검사한다.
- 이동 애니메이션 종료 시 해당 방의 적을 표시한다.
- 실제 도착 시점부터 고정된 적 판정 시각까지 선명도와 판정선 크기를 변화시킨다.
- 정확한 시각 이후에도 판정 링은 고정 두께로 안쪽으로 축소한다. 흰 아웃라인과의 겹침 종료를 실패 시각과 일치시킨다.
- 선택된 적에 점을 표시하고 대상 변경·처치·방 전환 시 갱신한다.
- 사격 성공 시 적을 즉시 처리하고, 적을 놓치면 즉사한다.
- 현재 방의 적 전부 → 다음 문 → 다음 방 순서로 채보를 연결한다.

완료 기준:

- 적이 이동 완료 전에는 나타나지 않으며, 도착 시각과 무관하게 판정 시각은 음악에 고정된다.
- 중앙선에 가장 가까운 적과 표시점, 실제 클릭 대상이 일치한다.
- 적과 문이 함께 보일 때도 같은 대상 선택 규칙을 따른다.
- 마지막 방에 적이 있다면 그 적까지 처리해야 클리어한다.

### 5단계 — 채보 검증과 초기화 완성

작업:

- 다음 항목을 편집 단계에서 확인할 수 있는 검증 기능을 만든다.

| 검사 | 확인 내용 |
| --- | --- |
| 방 연결 | 다음 방이 상하좌우 인접 방인지, 순서와 ID가 유효한지 |
| 등장 | 방 등장 시각이 판정 시각보다 앞서는지, 문과 방의 등장 시각이 같은지 |
| 문 간격 | a가 양수인지, 문 처리와 이동 성공 구간의 순서가 가능한지 |
| 방 도착 | 가장 늦은 성공 이동 + 이동 시간 이후에도 첫 적을 볼 여유가 있는지 |
| 적 순서 | 적 처치 뒤에 문과 이동을 수행할 수 있는지 |
| 연속 이동 | 가장 늦게 이동해도 다음 이동 입력이 이동 애니메이션에 막히지 않는지 |
| 조준 | 적 배치 반지름과 호 설정이 일치하는지, 의도하지 않은 대상 가림이 있는지 |

### 사용자 플레이 확인 항목

1. MainScene을 재생하고 Game 뷰에 포커스를 둔 뒤 Space로 시작한다.
2. 위 표대로 진행하면서 다음 방과 회색 미래 방, 각 판정선의 크기·선명도를 확인한다.
3. 방 도착 후 나타난 적을 판정선이 겹칠 때 조준·클릭한다. 선택된 적에만 흰 점이 표시되는지 확인한다. 위 표에 따라 문 유무가 다른 구간을 진행하고 명중·사망·클리어 효과도 확인한다.

7. 반복 재시작 시 음악, 방과 문, 적과 선택점, 사각 판정선, 플레이어 위치, 판정 문구와 사격 표시가 초기화되는지 확인한다.

8. 편집 상태에서 채보 에셋의 Validate chart와 Game Session의 Validate scene and chart를 눌러 정상 검사 결과가 표시되는지 확인한다.

### 판정 및 외형 보완

- 영어 판정 문구와 색을 공통 정의로 관리한다. EARLY는 파랑, ACCURATE는 초록, LATE는 주황, TOO EARLY는 보라, TOO LATE는 빨강이다.
- 적 7개를 원형 본체 + 고정된 흰 원형 아웃라인 + 분홍색 축소 판정 링으로 변경했다. 정확한 시각에 두 링의 위치와 크기가 일치하고, 이후 그 크기를 유지한다.
- 벽은 흰색이며 민트색 사각 판정선이 벽의 중심선에 겹친다. 미래 방은 회색 구분을 유지한다.
- 모든 표시 오브젝트를 MainScene에 정적으로 반영했다. 로직 86개, 통합 시나리오 21개, 런타임·Inspector 컴파일 및 변경된 씬 참조 검사를 통과했다. Unity 화면 검증은 사용자 확인으로 남긴다.
### 판정 표시 가독성 수정

- 방 판정선 두께를 0.045에서 0.14로 늘렸다. 적의 흰 아웃라인과 색 판정 링은 같은 외경을 유지하면서 선폭을 약 2.5배 늘렸다.
- 적 명중은 원형 효과를 사용하고 문 명중은 사각 효과를 사용한다. 사망·클리어 효과도 원형으로 표시한다. 효과는 정적 씬 오브젝트를 재사용한다.
- HUD에 실제 폰트 에셋을 연결하고 시작 시 해당 폰트의 아틀라스 재질을 적용한다. 판정 글자 크기를 0.11에서 0.65로, 안내 글자를 0.42로 늘렸으며 렌더링 순서는 200으로 설정했다.
- 성공 판정 문구 표시 시간은 0.9초다. 컴파일·로직·통합·씬 참조 검사를 통과했으며 실제 Unity 화면 확인은 사용자 검증으로 남긴다.
### 겹침과 허용 판정 동기화

- 최신 기획을 기준으로 방/적 판정선의 정확 시각 이후 정지 규칙을 폐기했다. 정확 시각에 중심선이 일치하고, 이후에도 안쪽으로 축소하여 흰 선과 겹침이 사라지는 시각에 실패한다. 문은 기존 닫힘 연출과 시간 판정을 유지한다.
- `FirstMovement.asset`의 `judgmentLineWidth`는 벽·방 판정선·적 아웃라인·적 판정 링의 공통 두께다(현재 0.2). `timing.early/late`를 바꾸면 겹침 구간의 축소 속도가 함께 달라져 실제 허용 구간과 일치한다. 폭과 속도를 독립적으로 조절해 화면과 판정이 어긋나지 않도록 한다.
- 판정선 반경은 `ApproachGeometry`에서 계산한다. 허용 구간 전에는 예고 크기에서 첫 접촉 위치로 접근하고, 허용 구간에서는 두께와 시간에 비례해 이동한다. 정확 판정 세부 구간은 기존 `timing.accurate`를 유지한다.
- 적의 원형 선은 씬에 미리 배치한 LineRenderer로 변경했다. 반경만 바꾸고 두께는 유지한다. 런타임에 오브젝트나 컴포넌트를 생성하지 않는다.
- 중앙 통로는 2.8로 확대했다. 문도 같은 너비를 사용한다. 벽 중심을 방 경계 ±3에 배치해 인접 방과 겹치는 벽이 한 줄 두께가 되도록 했다.
- 순수 로직 170개(겹침 경계·두께·방/적 반경·비대칭 허용 시간 검사 포함), 실제 채보 통합 시나리오 21개, 런타임/Inspector 컴파일과 씬 참조 검사를 통과했다. Unity 실행과 실제 렌더링은 사용자 확인으로 남긴다.
### 일정한 판정선 축소 속도

- 예고 구간과 허용 구간의 속도를 나누지 않고 등장부터 실패 경계까지 하나의 속도를 사용한다. 선 두께를 유지하고 `두께 / 한쪽 허용 시간`으로 속도를 자동 산출한다.
- 채보 Inspector에서 `Timing tolerance (+/- sec)` 하나로 전후 허용 시간을 설정하고 계산된 `Approach speed`를 확인한다. 기존 비대칭 값은 전체 허용 구간 길이를 보존한 평균값으로 대칭화하여 게임 판정과 표시 양쪽에 적용한다.
- 처음 크기를 고정하는 설정을 제거했다. 시작 반경은 `기준 반경 + 남은 시간 × 속도`로 정해지므로, 등장 시점이나 빠름/느림 이동에 따른 적 표시 시점이 달라도 속도는 바뀌지 않는다.
- 현재 두께 0.2, 허용 시간 ±0.15초이므로 반경 축소 속도는 초당 약 1.333이다. 정확 시각에 중심선이 일치하고 +0.15초에 안쪽 겹침이 끝난다.
- 순수 로직 231개와 통합 시나리오 21개, 코드 컴파일 및 씬 참조 검사를 통과했다. Unity 실행 검증은 하지 않았다.
### 등장 선행 시간과 판정 범위 편집

- `Assets/RoomRhythm/FirstMovement.asset`을 선택하거나 MainScene의 Game Session Inspector에서 `채보 · 등장 · 판정 설정 열기`를 누른다. 편집 후 다음 Play 실행에 적용된다.
- `Room Lead Time`: 방 이동 판정 몇 초 전 등장하는지(기본 2초). 방과 문은 함께 등장한다. 개별 `appearTime` 입력은 제거하고 선행 시간에서 계산한다.
- `Enemy Lead Time`: 적 판정 몇 초 전 등장하는지(기본 1.5초). 해당 방 도착 전에는 표시하지 않는다. 적별 등장 시각에 맞춰 선명도를 변화시키며, 등장 전에는 조준점과 사격 대상에서 제외한다.
- `성공 허용 범위 (±초)`는 EARLY~LATE 전체 성공 구간(기본 ±0.15초), `ACCURATE 범위 (±초)`는 정확 구간(기본 ±0.05초)이다. 선 두께와 일정한 축소 속도는 이 범위에 맞춰 연결된다.
- 문 판정 전에 방이 나타나지 않거나 적을 읽을 시간이 부족하면 Validate chart/Validate scene and chart에서 오류를 표시한다. 판정 시각을 자동으로 밀지 않는다.
- 실제 테스트 채보의 방 등장 시각은 2·7·10·12·16초다. 판정 시각과 음악은 동일하다. 순수 검사 237개, 실제 채보 시나리오 21개, 런타임·Inspector 컴파일과 씬 검사를 통과했다. Unity 실행 검증은 하지 않았다.
### 시각적 겹침과 TOO LATE 불일치 수정

- 실패 시 판정선 반경을 `기준 반경 - 선 두께`에 고정하던 처리를 제거했다. 실패 화면에서도 선이 흰 테두리에 계속 접촉해 보이던 원인이었으며, 이제 프레임의 실제 시각만큼 안쪽으로 진행한 모습을 표시한다.
- Play 중 Chart 변경 시 모델은 이전 판정 시간을 복사해 유지하면서 화면만 새 설정을 사용하던 경로를 수정했다. Chart 변경을 감지하면 음악을 멈추고 판정 모델·벽 두께·판정선·적·조준을 함께 재설정한 뒤 시작 대기로 돌아간다. Space로 다시 시작한다. R 재시작도 최신 설정으로 모델을 재생성한다.
- 사각형 벽 8개와 판정선 4개의 실제 영역 교차를 계산하는 회귀 검사를 추가했다. 모서리 교차와 아주 작은 겹침까지 포함하여, 여러 두께와 허용 범위에서 시각 영역의 겹침과 성공 판정이 일치함을 확인했다.
- 순수 로직 검사 297개, 실제 채보 통합 시나리오 21개, 런타임·Inspector 컴파일과 씬 참조 검사를 통과했다. Unity 실행 중 렌더링과 실제 입력 검증은 사용자 확인으로 남긴다.
### 판정선과 입력 안내 동기화

- `W IN 1`은 남은 초가 아니라 남은 박자를 올림한 값이어서, 정확 시각 직전에도 1로 표시되었다. 박자 정수 표시를 제거했다.
- 성공 구간 전에는 `W IN 0.32s`처럼 초 단위로 표시한다. 성공 구간에서는 `W NOW / EARLY`, `W NOW / ACCURATE`, `W NOW / LATE`와 판정별 색을 표시한다. 문과 적도 같은 규칙을 사용한다.
- 화면 안내는 판정선에 전달한 동일한 음악 시각과 실제 판정의 TimingWindow.Judge를 사용한다. 0.01초 전, 첫 접촉, 정확 시각, 안쪽 겹침, 만료, 판정 범위 변경에 대한 회귀 검사를 추가했다.
- 순수 검사 304개와 통합 시나리오 21개, 런타임·Inspector 컴파일과 씬 참조 검사를 통과했다. Unity 실행 검증은 하지 않았다.
### 임시 개발용 판정 바

- 숫자 카운트다운/NOW 텍스트를 제거하고 MainScene 카메라 아래에 `Development Timing Bar`를 정적으로 배치했다. 다음 입력 종류(W/A/S/D 또는 사격)와 입력 후 판정 결과 텍스트는 유지한다.

- Chart의 허용 범위 변경에 맞춰 색 구간의 폭이 자동으로 바뀐다. 판정선 및 실제 판정과 같은 음악 시각을 사용한다. 대기·이동·클리어 시 숨기고 실패 시에는 실패 위치를 보여 준다.
- Inspector의 `Show During Development`를 끄면 숨길 수 있다. Unity Editor 또는 Development Build에서만 표시되며 일반 배포 빌드에서는 자동으로 숨긴다.

### 입력 배치보다 앞선 시간 초과 판정 수정

- 이전에는 Update 끝에서 현재 DSP 시간까지 모델을 진행했다. 다음 입력 배치에서 그 시각보다 이른 이벤트가 도착하면 RoomRun의 오래된 입력 차단에 걸려 무시되고, 이후 입력 누락으로 TOO LATE가 발생할 수 있었다.
- Dynamic 입력 업데이트 시작 시각을 배치 기준으로 기록한다. 수집한 이벤트를 타임스탬프 순으로 처리한 뒤, 확인한 배치 시각(또는 이미 처리한 이벤트의 최신 시각)까지만 모델을 진행한다. 화면·개발용 바도 그 동일한 시각으로 표시한다.
- 게임이 활성화된 동안 입력을 Dynamic Update로 처리하고, 비활성화되면 기존 Input System 업데이트 모드를 복원한다. 프로젝트 설정 파일은 변경하지 않는다.
- 개발 중 WASD를 입력하면 Console에 `[Rhythm Input]` 로그로 판정 기준과의 오차(ms), 이벤트 시각, 대상 시각, 전후 상태와 판정 결과를 기록한다. Room Session의 `Log Input Timing`으로 끌 수 있다.
- 실제 입력 이벤트 시각의 의미는 Unity 공식 InputAction.CallbackContext.time 문서를 확인했다: https://docs.unity3d.com/Packages/com.unity.inputsystem@1.11/api/UnityEngine.InputSystem.InputAction.CallbackContext.html
- 순수 로직에서 다음 배치로 전달된 유효 입력이 기존 순서에서 누락되는 경우를 재현했다. 수정 순서는 유효 입력을 처리하며, 진짜 늦은 입력과 미입력의 기존 실패 경계는 유지한다.
- 순수 검사 301개, 통합 시나리오 21개, 런타임·Inspector 컴파일과 씬 참조 검사를 통과했다. 사용자가 겪는 실제 Unity 환경에서 동일 원인인지 최종 확인하지 않았으므로 입력 로그와 플레이 검증이 필요하다.
### 문 닫힘 연출을 내부 확대 판정선으로 변경

- 문은 방과 함께 등장하는 순간부터 닫혀 있다. 문짝은 통로 너비에 맞춰 중앙에서 맞물린 위치에 고정한다. 기존 흐릿함→선명함 표현은 유지한다.
- 문마다 방 중심에 주황색 사각 판정선을 MainScene에 미리 배치했다. 내부에서 바깥으로 커져 문 판정 시각에 흰 벽과 일치한다. 민트색 이동 판정선은 바깥에서 안쪽으로 줄어드는 기존 동작을 유지한다.
- 주황색 선은 방 벽과 같은 두께이며, 허용 시간과 두께로 확대 속도를 계산한다. 느림 구간에도 계속 커지고, 문 파괴 시 숨긴다. 리셋 시 초기 상태로 복원한다.
- 문 확대 판정선과 흰 벽의 실제 사각형 교차 영역도 시간 판정과 일치하는지 검사했다. 순수 검사 361개, 통합 시나리오 21개, 컴파일과 씬 참조 검사를 통과했다. Unity 실행 검증은 하지 않았다.
### 문 등장 애니메이션 및 선명도 보완

- 문은 등장 직후 양쪽에서 닫히는 짧은 애니메이션을 유지한다. `Door Close Duration` 기본값은 0.2초이며, 사격 허용 구간보다 늦게 닫히지 않도록 남은 시간에 맞춰 제한한다. 주황색 내부 확대 판정선은 기존대로 문 사격 시각을 표시한다.
- `Appearance Start Alpha` 기본값은 0.05다. 방·문·적과 해당 판정선은 등장 시 흐릿하게 시작해 각자의 정확 시각에 불투명도 1이 된다. 이후에도 선명도를 유지한다. 일정한 판정선 이동 속도와 실제 판정 시간은 변경하지 않았다.
- 씬의 문짝도 열린 초기 위치로 배치했다. 재시작과 Chart 변경 시 등장 시각을 기준으로 애니메이션을 다시 계산한다.
- 컴파일, 기존 순수 검사 361개·통합 시나리오 21개와 씬 참조 검사를 통과했다. Unity 실행 검증은 하지 않았다.
### BPM 기반 커스텀 채보 편집기

- `Window > Gun > 박자 채보 편집기`에 전용 EditorWindow를 추가했다. Room Chart Inspector에서도 열 수 있다.
- 방 이동·문 사격·적 사격을 세 줄의 박자 그리드로 편집한다. 마디 이동, 박 분할(셋잇단 포함), 노트 선택·복제·삭제·개별 스냅, 시간순 목록과 방/적 ID·방향 편집을 제공한다.
- BPM, 첫 박 오프셋, 박 단위 성공/정확 범위와 방/적 등장 선행 시간을 초 단위 게임 데이터로 변환한다. 문과 이동의 차이는 moveDelay로 계산한다. 기존 판정선·개발용 바는 적용된 Chart 설정을 사용한다.
- 박자 초안과 적용된 게임 데이터를 분리했다. 음악과 시작 방도 초안에 포함된다. 기존 채보 가져오기, 초안 저장, Undo, 검증 후 적용을 지원한다.
- 채보 순서·ID·시간·등장·이동 소요 시간·음원 길이를 검사하며 실패하면 게임 데이터를 바꾸지 않는다. 열린 씬의 적용된 채보 연결 검사도 제공한다. 새 방과 적은 씬에 정적으로 배치하고 ID를 연결해야 하며 자동 생성하지 않는다.
- 사용 절차와 예시는 `채보 편집기 사용법.md`에 작성했다. 고정 BPM 편집을 지원하며 곡 중간 BPM 변경과 음원 미리듣기는 이번 범위에 포함하지 않는다.
- 박자 변환/검증 30개, 순수 로직 361개, 실제 채보를 가져와 다시 변환한 결과의 통합 시나리오 21개, 런타임·Editor 컴파일과 씬 참조 검사를 통과했다. Unity 실행 및 EditorWindow UI 검증은 사용자 확인으로 남긴다.
### 시각적 맵·채보·연출 에디터로 전환

- 기존 박자표 편집기 진입점을 `시각적 맵 에디터`로 통합했다. 곡/기본 설정 탭과 맵/채보/연출 탭을 분리했다.
- 맵 클릭으로 방 연결, 입구 문, 8방향 적을 배치한다. 방 이동과 카메라 위치 드래그, Shift/영역 다중 선택, 선택한 방 묶음 생성 및 공통 등장 박을 지원한다.
- 묶음 등장, 방/문/적 판정선 시작, 실제 판정 시각을 별도 데이터로 저장하고 런타임에 적용한다. 판정선의 일정한 속도와 허용 범위에 따른 시각적 겹침은 유지한다.
- 하단 타임라인에서 등장·판정선·입력·카메라 이벤트의 박 위치를 수정한다. 음악에 고정된 시간으로 2D 연출을 이동/재생해 본다. 미리보기는 무음이며 정확 입력 성공을 가정한다.
- 카메라 위치·크기·이동 지속 박·보간 및 흔들림 시작·지속·강도·빈도를 지원한다. 미리보기와 실제 재생이 같은 카메라 평가 함수를 사용한다. 이동 이벤트가 없을 때 플레이어 추적을 선택할 수 있다.
- `저장 · 씬에 적용`에서 초안 검증 후 기존 MainScene 템플릿으로 방/문/적을 편집 시점에 배치하고 Session/Combat을 연결한다. 생성된 배치를 검사한 뒤 기존 맵을 교체하며, 검사 실패 시 Undo로 롤백한다. 씬과 선택한 채보 에셋을 저장한다. 실행 중 오브젝트 생성은 하지 않는다.
- 순수 맵/카메라 검사 44개와 기존 로직/채보 검사, 런타임/Editor 컴파일 및 기존 씬 참조 검사 통과. Unity를 실행하지 않았으므로 실제 창 조작·씬 저장·Undo 및 Play 검증은 사용자 확인이 필요하다.
### 시각적 편집 흐름 및 좌표 재방문 개선

- 도구별 입력 분기를 분리해 선택/Bundle 모드의 클릭은 선택만 수행한다. 방 추가는 위치를 먼저 지정하고 빈 박자 입력 칸에 숫자를 입력한 뒤 확정한다. 타임라인 커서 시각을 방의 박자로 자동 사용하지 않는다.
- 방은 순서/입력 박인 `nth/nbeat` 형식으로 표시하고 Bundle 이름을 사용한다. 진행 방향 화살표를 추가했으며 같은 좌표의 방문 텍스트는 시간순으로 아래에 쌓고 개별 선택할 수 있다.
- 좌표 중복 자체를 금지하던 검증을 제거했다. 방문마다 별도 ID를 유지하고 같은 좌표의 이전 방이 늦은 성공 입력과 애니메이션까지 마친 뒤 재등장하는 경우를 허용한다. W 다음 S로 시작 위치에 돌아오는 채보의 컴파일·완주와 등장 충돌 경계를 검사했다.
- 전체 맵 / 편집 가능한 미리보기 / 읽기 전용 연출 재생 모드로 분리했다. 미리보기와 재생 모드에서 흰 기준선을 드래그할 수 있다. 재생 중 스크럽은 드래그 동안만 멈추고 놓으면 이어진다.
- 카메라 배치를 카메라 조작으로 바꾸고 흔들림 추가와 목록을 그 패널로 통합했다.
- 타임라인은 Bundle·문·방·적·카메라·흔들림 순서다. 판정선 시작과 정확 입력을 하나의 구간으로 연결하고 양 끝 수정 및 구간 전체 이동을 지원한다. 시간상 겹치는 구간은 내부 행을 나눠 표시한다.
- 맵/카메라 로직 검사 51개, 기존 로직/채보 검사와 런타임·Editor 컴파일, 기존 씬 참조 검사를 통과했다. Unity 실행 검증은 하지 않았다.
### 편집 영역 크기 및 타임라인 탐색

- 맵/속성 영역과 타임라인 사이에 드래그 가능한 경계선을 추가했다. 두 영역의 최소 높이를 보장하고 창 크기가 변해도 조절한 비율을 유지한다.
- 타임라인 눈금·구간 영역에서 우클릭 드래그로 좌우 탐색한다. 기존 시작 박 입력과 좌우 버튼을 대체하며 표시 박 수 및 현재 시각으로 이동 기능은 유지한다.
- 드래그 중 마우스가 맵 영역으로 넘어가도 입력 소유권을 유지해 맵 이동이나 노트 수정으로 전환되지 않게 했다. 재생 전용 모드에서도 크기 조절과 탐색이 가능하다.
- 런타임/Editor 컴파일과 기존 자동 검사를 통과했다. Unity UI 실행 검증은 하지 않았다.
### 방 중심 편집 및 저장 검증 완화

- 문 판정선 시작이 너무 이르다는 기하 제한과 자동 맞춤 UI를 제거했다. 음수 반경 구간은 기존 렌더링의 0 반경 처리를 사용한다. 판정선 시작이 성공 구간 안이라는 이유만으로도 차단하지 않는다. 입력 이후의 시작 등 명백한 시간 오류 및 플레이 불가능한 데이터 검사는 유지한다.
- Bundle UI·타임라인을 제거하고 방별 등장 박을 추가했다. 기존 group 데이터는 마이그레이션 호환용으로만 남기며 창에서 기존 등장 시각을 각 방에 복사하고 그룹을 비운다.
- 상단 도구 탭을 없애고 선택한 방의 패널에서 추가·이동·문·8방향 적·카메라·흔들림을 설정한다. 격자 X/Y 표시는 제거했다. 같은 칸에 여러 방이 있으면 이름 텍스트로만 방문을 구분해 선택한다.
- 맵 로직 검사 53개, 기존 검사 및 런타임/Editor 컴파일, 씬 참조 검사 통과. Unity 실행 검증은 하지 않았다.
