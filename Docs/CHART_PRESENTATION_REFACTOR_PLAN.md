# 전체 채보 기반 보스 연출 개편 계획

작성: 2026-10-03. 상태: **사용자의 새 전체 채보에 복도 적 출현 → 2칸 폭 사무실 → 15박 인트로 → 위쪽 창문 파괴·탈출을 연결했다. 클립 15개는 좁힌 몸통/어깨에 맞춰 조정했다. 이후 보스전·홀·범용 연출 편집기와 Unity 실행 확인은 남아 있다.**

이 문서는 개편 기준과 진행 상태다. 단계별 목표는 완료 표시가 없는 한 구현 사실이 아니다. 실행 중인 구조는 `PROJECT_STRUCTURE.md`에서 확인한다.

## 1. 확정 목표와 제작 흐름

1. 사용자가 기존 시각적 맵 에디터에서 한 곡의 **전체 채보**를 완성한다. 일반 적 구간, 보스 등장 동안의 입력 공백, 보스전, 마지막 판정까지 같은 채보에서 편집한다.
2. Unity 기본 Animation 창에서 보스 모션을 만들고, 별도의 연출 편집 흐름에서 클립·경로·필요한 외형을 채보 액션에 연결한다. 외부 편집은 맵 에디터 밖의 제작 도구를 뜻하며, 다른 플레이 씬을 뜻하지 않는다.
3. 한 스테이지 씬, 한 실행 채보, 한 음악 시계에서 재생한다. 보스 등장·퇴장을 위해 채보나 씬을 바꾸지 않는다. 허브 입장·복귀는 기존 씬 이동을 유지한다.
4. 연출이 연결되지 않은 액션은 기존 일반 표시를 사용한다. 보스 연출이 판정이나 점수를 추가하지 않는다.

| 기본 액션 | 유지할 게임 동작 | 교체할 수 있는 표시 |
| --- | --- | --- |
| 방 이동 | 기존 방향·시각 판정, 성공 이동, 도착 상태 | 사용자가 정할 이동 시점의 모션·외형 |
| 문 부수기 | 기존 문 파괴 판정 및 이동 가능 조건 | 사용자가 정할 대상 외형·성공/실패 반응 |
| 적 쏘기 | 기존 사격 판정, 대상 선택·활성 구간 | 사용자가 정할 대상 외형·모션·성공/실패 반응 |

이전에 제시된 방 파괴·피신, 보스 벽, 탄환 요격은 설명용 예시였으며 구현 요구사항으로 사용하지 않는다. 실제 외형과 모션은 사용자가 제작하면서 정한다. 현재 마피아 씬에 저장된 콘텐츠도 최종 기획으로 고정하지 않는다.

최종 제작은 전체 채보를 완성한 뒤 연출을 연결하는 순서다. 새 마피아 흐름은 [MafiaStage01 목표 연출](../Assets/Scenes/Stages/MafiaStage01.md)에 기록한다. 일반 구간→책상에서 대치·AK 3발·위쪽 창문 탈출→부하 방패와 난사→긴 복도→기둥으로 나눈 3×3 홀 순서다. 보스의 양팔 견착·부위 피격과 중앙 칸 안의 위치 조정도 이 문서를 기준으로 한다. 이는 앞서 철회한 일반 예시와 별도로 사용자가 지정한 실제 제작 요구다.

이 흐름을 채보로 작성하려면 적 자유 배치, 복도 내부 이동, 홀 외형과 반복 방문의 분리가 먼저 필요하다. 기본 Animation 창을 익힐 때는 `MAFIA_MOTION_PRACTICE.md`를 사용한다. 기존 오른팔 클립은 학습용이며 최종 총기 모션은 양팔 견착으로 새로 준비한다.

모든 보스가 세 액션을 조합해 사용한다. 보스마다 별도 판정 모델·피해량·물리 충돌 규칙을 만들지 않는다. 외형 변경 때문에 실제 조준 위치가 달라질 수 있으므로, 표시와 대상 선택은 같은 위치 평가 함수를 사용한다.

## 2. 반드시 보존할 동작

- `RoomRun`의 상태 전이, 이동·문·적 판정 경계, 입력 순서, 정확도 계산을 기준으로 삼는다. 구조를 개편한다는 이유로 판정 엔진을 다시 쓰지 않는다.
- 이동 중 추가 이동 입력 무시, 이동 중 사격, 문을 파괴한 뒤 이동, 사망·클리어·재시작, 곡별 입력 오프셋을 유지한다.
- 입력 없는 공백에서도 음악과 연출 시계는 계속 흐른다. 공백은 새 채보 전환이나 강제 클리어가 아니다. 잘못된 수동 입력 처리도 기존 규칙을 유지하며 별도 무적 구간을 암묵적으로 추가하지 않는다.
- 허브 곡 선택, 기록 저장·최고 기록, 디버그 자동 진행과 기록 저장 제외를 유지한다.
- 기존 일반 씬·튜토리얼은 보스 연출을 연결하지 않아도 기존과 동일하게 동작한다.
- 방 도착 후 뒤 통로 닫힘, 다음 이동이 같은 통로로 되돌아가면 닫힘 생략을 유지한다. 보스 연출이 해당 통로의 표시를 맡을 때 기본 연출과 중복하지 않도록 소유권을 지정한다.
- 판정선 색·읽기 쉬운 예고를 유지한다. 보스 외형에 흑백 화면 연출을 적용하더라도 판정 표시를 임의로 바꾸지 않는다.
- 방·캐릭터·표적·효과용 오브젝트는 씬·프리팹에 미리 배치한다. 실행 중 생성·파괴로 연출을 구현하지 않는다. 필요한 추가 배치는 편집 단계에서 저장한다.
- Unity 실행·Play Mode 검증은 사용자가 담당한다. 개발자는 코드 컴파일, 순수 모델·이관 검사와 허용된 범위의 정적 확인을 수행한다.

| 현재 영역 | 확인한 상태 | 개편 방향 |

## 4. 목표 책임과 데이터 계약

### 4.1 채보가 액션과 시간을 소유한다

- 채보는 세 액션의 기준 시각, 등장 시각, 방 연결, 이동 시간·방향, 대상 ID를 소유한다.
- 연출 연결 키는 **액션 종류 + 안정적인 노트 ID**다. 배열 순번·이름·절대 시각·Transform 인스턴스를 키로 쓰지 않는다.
- 현재 이동/문은 `MoveNote.destinationId`, 사격은 `EnemyNote.id`를 사용한다. 1차 구현은 이 ID와 역할을 조합해 호환시키고, 식별이 불안정한 편집 경로가 확인되면 버전 있는 이관으로 별도 노트 ID를 도입한다.
- 이동과 문이 같은 destinationId를 써도 역할이 달라 충돌하지 않아야 한다. 같은 물리 방을 다시 방문하는 별도 노트도 식별할 수 있어야 한다.
- 시간 이동·정렬·이름 변경·저장/불러오기·씬 적용·Undo/Redo는 기존 ID를 보존한다. 복제는 새 ID를 발급한다. 삭제·종류 변경·중복 ID는 연결 오류로 표시하며 가까운 다른 노트에 자동 연결하지 않는다.

### 4.2 연출은 채보를 참조한다

제안 구성명은 구현 시 기존 코드와의 중복을 검토해 확정한다.

| 책임 | 저장할 내용 / 경계 |
| --- | --- |
| 연출 데이터 에셋 | 액션 키, 모션 클립, 역할별 외형 설정, 기준 이벤트, 상대 시각, 경로·표시 파라미터 |
| 씬 연결 컴포넌트 | 에셋의 대상 키에 대응하는 보스 리그·표적·방 외형·효과·경로 기준점 참조 |
| 액션 조회·검증 | 현재 채보에서 키를 해석해 시각·방·대상 제공. 누락·중복·충돌 검출 |
| 연출 평가기 | 절대 곡 시각 및 실제 판정 결과를 받아 자세·외형 평가. 판정 모델 수정 금지 |
| 외부 연출 편집기 | 채보를 읽기 전용으로 표시하며 연결·클립·경로·시점 편집 및 미리보기 |

씬 참조는 씬 연결 컴포넌트에 둔다. 재사용 에셋에 씬 인스턴스를 직접 저장하지 않는다. 런타임 평가기와 편집기 전용 미리보기 코드를 분리한다.

### 4.3 시간을 복사하지 않고 기준점에 연결한다

- 공격 예고·발사·도착은 해당 노트의 등장 또는 정확 판정 시각에 상대 박자/초를 더해 계산한다. 독립된 `shots.time` 복사본을 두지 않는다.
- 성공/실패/이동 도착 반응은 실제 `RoomActionResult`의 발생 시각을 사용한다. 이른/늦은 성공에서도 적중·파괴 반응이 정확 판정 시각을 무조건 기다리지 않는다.
- 입력 공백의 등장 연출은 앞/뒤 노트의 기준 시각과 오프셋에 연결하거나 명시적인 곡 박자 기준 큐를 사용한다. 곡 고정 큐는 노트 이동을 따라가지 않는다는 것을 편집기에 구분해 표시한다.
- 음악 시각과 입력 보정된 판정 시각의 변환을 한 곳에 둔다. 이벤트가 어떤 시계의 값인지 명시한다. 프레임 시각으로 판정 발생 시각을 덮어쓰거나 오프셋을 중복 적용하지 않는다.
- 노트 시각·BPM·음악 지연을 바꾸면 연결된 발사·표적 도착·클립 배치를 다시 계산한다. 데이터 갱신 후 오래된 시간 캐시를 계속 쓰지 않는다.
- 맵 에디터의 채보 편집은 연출 키프레임을 직접 수정하지 않는다. 연출 편집기에서 노트를 옮기려면 맵 에디터의 해당 노트로 이동하게 한다.

### 4.4 외형과 상태의 소유권

- 일반 표시를 기본 구현으로 둔다. 외형 대체가 유효하게 연결된 액션만 해당 표시를 끄고 전용 표시를 사용한다.
- 이동 판정과 이전 방 숨김을 분리한다. 연결된 연출에 필요하면 이전 방 외형을 연출 종료까지 유지할 수 있지만, 이미 떠난 방의 판정·충돌·적 활성 상태는 되살리지 않는다.
- 재방문 방과 이전 방문의 연출이 겹칠 때는 사전 배치된 연출용 외형을 사용하거나 배치를 검증에서 거부한다. 실행 중 방을 복제하지 않는다. 이전 연출이 새 방문의 방을 숨기지 않아야 한다.
- 표적의 `PositionAt(time)`는 부작용 없는 함수로 유지한다. 같은 입력 시각의 조준 위치와 표시 위치가 같아야 하며 물리 충돌로 추가 성공·실패를 만들지 않는다.
- 루트 경로, 관절 AnimationClip, 색·표시 상태의 소유자를 분리한다. 기존 Director·Animator·클립이 같은 Transform을 동시에 쓰지 않게 검증한다.
- 보스의 기본 모션·총기 반동·맞은 부위의 변위를 합쳐 최종 자세를 한 번 적용한다. 보스 노트와 부위에 해당하는 명중만 반응하며, 일반 적·문 성공을 보스 피격으로 처리하지 않는다. 연속 명중의 반응을 보존하고 변위 누적을 제한한다.
- 카메라 구도·줌·레터박스의 제어권도 명시한다. 맵 카메라, 인트로 연출과 사망 연출이 동시에 덮어쓰지 않게 한다. 타격감 연출은 음악·판정 시계를 정지하거나 느리게 하지 않는다.
- 같은 명중 반응을 `OnHit`와 `OnAction` 양쪽에서 실행하지 않는다. 지속 자세는 시각으로 평가하고, 단발 효과는 이벤트 식별자로 실행당 한 번만 처리한다.
- 재시작은 음악·판정·입력 큐·연출 처리 이력·표적 경로·방 외형·보스 자세·활성·색·Animator 상태를 처음 상태로 복원한다. 다시 시작해도 숨겨진 외형이나 잔여 효과가 남지 않아야 한다.

## 5. 구현 순서와 단계별 완료 조건

### 0단계 — 기존 동작 기준과 이관 목록 확보

- 관련 기존 검사와 컴파일을 실행하고 결과를 기록한다. 계획 작성 시 새로 통과했다고 간주하지 않는다.
- 일반 플레이·디버그의 판정 이벤트 종류/ID/발생 시각/등급/점수/최종 상태를 비교할 회귀 사례를 확보한다. 정답 입력뿐 아니라 이른/늦은 성공, 실패, 재시작도 포함한다.
- 기존 두 채보, 맵 편집 원본, 클립·타임라인, 씬 연결과 사용자 수동 편집을 대상별로 목록화한다. 요청 범위 밖의 전체 탐색은 하지 않는다.
- 복원 가능한 사본과 변환 보고서 저장 위치를 정한다. 백업 없이 기존 에셋에 변환 결과를 덮어쓰지 않는다.

완료: 무엇을 유지·이관·제거할지와 비교 기준이 명확하며, 현재 코드가 검증 가능한 상태다.

### 1단계 — 단일 전체 채보로 이관 (저장 결과 적용 완료)

- 일반/보스 채보를 곡 절대 시각을 유지한 채 한 채보로 변환한다. 일회성 변환 도구와 비교 검사는 이관 검증을 마쳐 제거했다.
- 일반 마지막 방과 보스 시작 방의 중복 경계를 연결하고 ID 대응표를 만든다. 시간·방 좌표·문/적·맵 그룹·카메라 키·표적·오프셋을 함께 이관한다. 노트 배열만 붙여 맵 편집 원본을 잃지 않는다.
- 경계에 가짜 이동/문/사격을 추가하지 않는다. 보스 등장 공백은 다음 노트까지 시간 간격으로 표현한다. 구간별 판정 합계는 변하지 않아야 한다.
- 한 `RoomRun`에서 노트 간 입력 공백을 지나 다음 노트로 진행한다. 구간 교체 의존성과 호환 분기는 제거했다.
- 맵 에디터에서 전체 곡을 읽기→편집→저장→씬 적용→재열기 할 수 있게 한다. 기존 씬 참조 전환은 변환 검증 성공 후 수행한다.

완료: 같은 씬의 한 채보로 처음부터 마지막까지 판정 가능하고, 등장 공백에서 조기 클리어·음악 정지·채보 교체가 없다.

### 2단계 — 액션 연결과 연출 평가 계약 도입

#### 선행 작업: 새 채보 제작을 위한 기반

- **구현 완료, Unity 확인 대기:** 적을 선택했을 때만 좌표 입력을 제공하고 맵에서 직접 드래그할 수 있다. 방 기준 자유 좌표와 기존 8방향을 선택하며, 드래그는 놓을 때 한 번 적용하고 Esc로 취소한다. 맵·비트·실행 노트 변환, 복제·Undo/Redo·저장·씬 적용/가져오기·런타임 설정에 좌표를 연결했다. 기존 에셋은 기본 8방향 배치를 유지한다.
- 긴 복도의 방 내부 이동 경로와 진행 시각을 편집한다. 미리보기·실행·이동 중 사격이 같은 플레이어 위치를 사용하고, 새 이동 노트를 임의로 끼워 넣지 않는다.
- 3×3 홀의 외벽·기둥 외형을 칸별 판정과 분리한다. 같은 공간의 반복 방문은 서로 다른 이동/문 노트로 식별하고, 홀 외형을 다시 생성하거나 방문마다 사라지게 하지 않는다.
- 중앙의 같은 보스를 여러 사격 노트가 참조할 수 있게 한다. 첫 사격 후 외형은 유지하고, 2발은 두 판정과 두 번의 부위 반응으로 처리한다.

선행 완료: 사용자가 맵 에디터에서 새 마피아 전체 채보를 작성·저장·다시 적용할 수 있고, 기존 일반 채보의 위치·판정·재시작은 유지된다.

#### 액션과 연출 연결

- 액션 조회·ID 보존·연결 검증을 먼저 구현하고, 채보를 옮겼을 때 연출 기준 시각이 자동 갱신되도록 한다.
- 기존 문/적 외형 대체 계약을 활용하고 이동 액션의 표시 제어를 추가한다.
- 기본 외형 경로와 전용 연출 경로를 명시적으로 선택한다. 연출 미지정은 정상적인 기본 표시, 잘못 연결된 연출은 제작 오류로 구분한다.
- 노트 삭제·중복·종류 변경·씬 재적용 시 잘못된 참조를 숨기지 않는다. 실제 삭제나 재생성 전에 오류를 보고하고 부분 적용을 되돌릴 수 있게 한다.

완료: 이동·문·사격 각각 하나에 연출을 연결하고, 동일 입력의 판정 결과가 기본 표시일 때와 같다.

### 3단계 — 별도 연출 편집기와 모션 연결

- 전체 채보를 참조하는 새 연출 편집 흐름을 만든다. 구형 등장 전용 창은 제거한 상태다. 먼저 액션 선택→모션/표적 연결→상대 시각→미리보기의 최소 경로를 완성한다.
- 노트 기준 큐와 곡 기준 큐를 구분해 표시한다. 보스 등장처럼 입력 없는 구간도 편집할 수 있다.
- 외부에서 만든 AnimationClip을 연결하고 동작별 길이·시점·경로를 수정한다. 보스마다 별도의 거대한 맵 에디터를 만들지 않는다.
- Unity Timeline 재사용과 기존 경량 평가기의 재사용을 3단계 시작에 비교한다. 선택 기준은 노트 시간 변경 추종, 편집 편의, 절대 시각 평가, Transform 소유권, 복원 가능성이다. 두 개의 연출 시간 원본을 유지하는 구현은 채택하지 않는다.
- 수동 탐색/음악 재생/성공·실패 반응 미리보기를 분리한다. 역방향 탐색은 실제 판정·기록·구간 전환을 실행하지 않는다. 실제 플레이와 같은 연출 평가 코드를 사용한다.
- 종료·창 닫기·씬 저장·재컴파일·Undo/Redo·Play Mode 진입에서 원래 씬 상태를 복원한다. 미리보기 중 런타임 오브젝트를 만들지 않는다.

완료: 보스 코드를 고치지 않고 채보 노트의 연출을 연결·수정할 수 있고, 미리보기 후 씬 상태가 오염되지 않는다.

### 4단계 — 마피아 콘텐츠 전체 연결과 기존 연출 이관

- 사용자 지정 마피아 목표 연출에 따라 인트로·전투·마무리를 연결한다. 현재 초안의 위쪽에서 다가오는 등장이나 탄환 요격 배치를 최종 콘텐츠로 유지할 의무는 없다. 대체 경로가 작동하기 전까지 기존 코드는 보존한다.
- 사용자가 정한 액션에만 필요한 모션·외형 대체를 연결한다. 모든 액션의 외형을 반드시 바꾸지는 않으며, 연결한 연출은 기존 기본 판정 이벤트로 구동한다.
- 새 채보의 액션 키에 예고·발사·반응 시각을 연결한다. 사무실은 방 도착·창문 노트에 연결했고 구 고정 Shots·표적은 제거했다. 이후 보스전 표적은 새 기획에 필요한 것만 만든다.
- 마지막 노트 처리와 클리어 시점을 분리해 퇴장 연출을 처리한다. 새 판정이나 가짜 끝 노트 없이 클리어·기록·복귀가 정확히 한 번 발생하게 한다.
- 허브 진입, 씬 직접 실행, Debug Mode에서 모두 같은 전체 채보를 사용한다.

완료: 사용자가 한 씬에서 전체 맵 채보를 수정하고 별도 연출 도구로 보스 표시만 수정할 수 있다.

### 5단계 — 검증 후 구 코드·구 에셋·문서 제거

- 구간 전환 경로·변환 전 채보·등장 전용 창과 에셋 타입은 제거했다. 마피아 직접 오른팔 모션·독립 Shots는 사무실 클립 경로로 교체했고 관련 구 표적/경로를 씬에서 제거했다. 실제 참조와 대체 여부로 판단한다.
- 직렬화된 컴포넌트/ScriptableObject 타입은 먼저 참조와 데이터 이관을 마친 뒤 삭제한다. Unity가 새 스크립트·필드를 인식한 상태에서 Missing Script·누락 에셋을 확인한다.
- 씬·에셋·Editor·검사·제작 도구·문서의 삭제 대상 참조를 함께 제거한다. `.meta`는 삭제한 Unity 에셋의 대응 파일만 함께 정리한다. 사용하지 않는 호환 코드·fallback을 무기한 남기지 않는다.
- 사용자 Unity 확인 전에는 구 에셋 원본 또는 복원 사본을 보존한다. 확인하지 못한 항목을 완료로 표시하지 않는다.
- 구조 요약과 최종 사용 문서를 새 흐름에 맞게 갱신한다. 해당 코드가 사라진 시점에 구간 제작 등 이전 사용 문서도 제거한다.

완료: 새 제작 흐름만으로 스테이지 제작이 가능하고, 제거한 구현의 참조나 병렬 편집 창이 남지 않는다.

## 6. 검증표와 중단 기준

| 검증 영역 | 확인할 사례 | 통과 조건 |
| --- | --- | --- |
| 판정 보존 | 일반/보스 표시, 정답·이른·늦은 입력, 실패, 프레임 지연 | 이벤트·등급·점수·진행 결과가 연출 유무와 무관하게 같음 |
| 한 채보 이관 | ID 매핑, 경계 방, 노트 수·시각·방향, 적 소속, 문 시각, 음악 설정 | 누락·중복·가짜 경계 노트·시각 변경 없음 |
| 입력 공백 | 등장 중 무입력, 공백 전후 입력, 마지막 판정 후 퇴장 | 음악 연속, 중간 클리어 없음, 기존 입력 규칙 유지 |
| 시간 연동 | 노트 이동, BPM/음악 지연 변경, 오프셋 적용, 재정렬 | 해당 노트 기반 연출만 함께 이동하고 이중 보정 없음 |
| 참조 보존 | 저장/재열기, 복제/삭제, Undo/Redo, 맵 씬 재적용 | ID와 유효 연결 유지, 누락은 명시 오류, 부분 적용 복구 |
| 적 자유 배치·복도 | 임의 위치, 방 이동, 저장/재적용, 걷는 중 사격 | 에디터·실행 위치와 과거 입력 시점의 조준/명중 위치 일치, 기존 위치 보존 |
| 3×3 홀 | 같은 칸 재방문, 문 사격 후 복귀, 중앙 보스 1발/2발 | 홀 외형 유지, 방문별 노트 구분, 두 캐릭터 겹침 없음, 명중마다 한 반응 |
| 모션·피격 | 양팔 견착, 방향 전환, 연사, 부위별 연속 명중, 일반 적 처치 | 손·총·어깨 접점 유지, 올바른 부위만 반응, 음악/판정 시계 불변 |
| 이동 연출 | 이전 방 표시 유지/숨김, 빠른 다음 이동, 재방문, 뒤 통로 닫힘 예외 | 판정 방과 표시 방 분리, 현재 방·미래 방문 표시를 잘못 숨기지 않음 |
| 문·사격 외형 대체 | 이동 중 사격, 동일 시각 입력, 실제 과거 입력 시점, 성공/실패 | 위치 평가 일치, 기본 외형 중복 없음, 반응 중복 없음 |
| 재시작 | 공백·보스전·사망·퇴장 중 재시작을 여러 번 반복 | 처음 시계·점수·입력·외형·클립 상태로 복원 |
| 미리보기 | 앞으로/뒤로 탐색, 동일 시각 반복, 종료/저장/재컴파일/플레이 전환 | 같은 자세 재현, 게임 상태·기록 불변, 원본 씬 복원 |
| 기존 기능 | 튜토리얼·허브·곡 선택·기록·디버그 자동 진행 | 기존 동작 유지, 디버그 기록 미저장 |

`Tests/RoomRhythm/Run-Checks.ps1`를 기본으로 단계별 필요한 검사만 추가한다. 이관 검사는 기존 파일의 특정 ID·개수만 하드코딩한 통과 조건 대신 변환 전후 의미 비교를 포함한다. `MafiaStageChecks.cs`와 씬 검사는 현재 전체 채보를 직접 읽는다. 완료된 변환 도구에 의존하지 않는다.

컴파일·순수 모델 검사는 개발자가, 실제 애니메이션·음악 동기화·씬 저장/복원·리그·사격 체감은 사용자가 Unity에서 확인한다. 씬·프리팹 YAML 직접 조사나 검사는 해당 파일 작업이 요청된 범위에서만 수행한다.

판정 차이, 참조 유실, 원본 덮어쓰기, 미리보기 상태 저장, 재시작 잔여 상태가 발견되면 해당 단계의 전환·삭제를 중단하고 원인을 고친다. 문제를 없애기 위해 기존 기대값을 새 결과에 맞춰 바꾸지 않는다. 사용자 승인 없는 기획·난이도 변경으로 해결하지 않는다.

## 7. 문서 정리 및 현재 호환 상태

이번 계획 문서로 과거 보스 인계, 등장만 편집하는 별도 안내, 최초 프로토타입 구현 계획을 대체한다. 초기 계획의 새 MainScene·기존 프로토타입 전부 삭제 지시는 현재 작업에 적용하지 않는다.

기획 원문, 현재 맵 에디터 사용법, 현재 씬/표적/재시작/검사 안내는 유지한다. 이 문서들은 코드가 실제로 교체되기 전까지 유지보수에 필요하며, 전체 채보 기반의 새 제작 흐름이 이미 구현되었다는 근거로 사용하지 않는다.

저장된 마피아 씬은 전용 타임라인 에셋 없이 기본 등장 연출을 사용한다. 연결된 데이터가 없는 구형 등장 편집 도구는 메뉴·Inspector 버튼·전용 에셋 타입과 함께 제거했다. 기본 등장·전투·퇴장과 재시작은 유지한다. 전체 채보를 참조하는 새 외부 연출 편집기는 아직 구현하지 않았다.
